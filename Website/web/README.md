# Web-ready images

Generated by `tools/build_web_images.py`. **Do not edit by hand** — re-run the
script instead.

The files in the project folders one level up (`Website/1. B&B Clubview/` etc.)
are print/archive masters: uncompressed PNGs, several up to 23 MB and 13 000 px
wide. They are the right thing to keep, and the wrong thing to serve. This
folder holds the versions the site should actually link to.

| | Masters | Served from `web/` |
|---|---|---|
| Whole site, all 74 images | 294.5 MB | 9.9 MB |
| Heaviest project page (Erf 1839 Nelspruit, 11 images) | 79.5 MB | 1.9 MB |
| Heaviest single image (`7_Axo Cut 02.png`) | 23.2 MB | 144 KB at 1920w |

## Layout

```
web/
  manifest.json
  1-b-and-b-clubview/
    axo-cut-02-640.webp
    axo-cut-02-1280.webp
    axo-cut-02-1920.webp
    axo-cut-02-2560.webp
    ...
```

Widths are 640 / 1280 / 1920 / 2560, and are only emitted when the master is at
least that wide — nothing is ever upscaled. Folder and file names are slugged,
so no spaces or `&` in URLs.

## manifest.json

One entry per image, already sorted into the display order the `N_` filename
prefixes encode (intro sketch, renders, plans, elevations, axo view, axo cut):

```json
{
  "slug": "axo-cut-02",
  "role": "axo-cut",
  "order": 7,
  "master": "1. B&B Clubview/7_Axo Cut 02.png",
  "width": 11357, "height": 8139, "aspectRatio": 1.3954,
  "lqip": "data:image/webp;base64,...",
  "sources": [{ "width": 640, "height": 459, "bytes": 17652, "src": "..." }]
}
```

`width`/`height` are the master's. Use each source's own `width`/`height` on the
`<img>` so the browser reserves space before the image arrives — that is what
stops the page jumping around as it loads.

## Using them

```html
<img
  src="/web/1-b-and-b-clubview/axo-cut-02-1280.webp"
  srcset="/web/1-b-and-b-clubview/axo-cut-02-640.webp   640w,
          /web/1-b-and-b-clubview/axo-cut-02-1280.webp 1280w,
          /web/1-b-and-b-clubview/axo-cut-02-1920.webp 1920w,
          /web/1-b-and-b-clubview/axo-cut-02-2560.webp 2560w"
  sizes="(max-width: 800px) 100vw, min(1600px, 90vw)"
  width="1280" height="917"
  loading="lazy" decoding="async"
  alt="B&B Clubview — cutaway axonometric">
```

Three rules that matter more than the compression:

1. **`sizes` must describe your real layout.** If it says `100vw` but the image
   renders in a 400 px column, every visitor downloads the 2560w file and the
   work here is wasted.
2. **`loading="lazy"` on everything below the fold** — but *not* on the first
   image on the page. Lazy-loading the hero delays the largest contentful paint
   instead of helping it.
3. **Always set `width` and `height`.** Cheapest layout-stability win there is.

For the one hero image per page, preload it and skip lazy loading:

```html
<link rel="preload" as="image"
      href="/web/1-b-and-b-clubview/render-01-1280.webp"
      imagesrcset="..." imagesizes="...">
```

`lqip` is a ~24 px blur placeholder, small enough to inline as a CSS
`background-image` behind the real image so there is something on screen
immediately.

## Caching

These filenames are stable, so a long cache is safe once you are happy with the
output. On Netlify (`_headers`) or Cloudflare Pages:

```
/web/*
  Cache-Control: public, max-age=31536000, immutable
```

Serve `manifest.json` with a short TTL instead, since it changes whenever images
are added.

## Regenerating

```sh
pip install Pillow
python3 tools/build_web_images.py          # only rebuilds what changed
python3 tools/build_web_images.py --force  # rebuild everything
```

`WIP/` and `_CX/` are treated as internal working folders and skipped. Pass
`--include-wip` if any of those images need to go on the site.
